# QuickProp Office — AI Bulk Mandate Import & Listing Creation

Build a desktop-first **QuickProp Office Bulk Mandate Import System** designed specifically for the initial onboarding of estate agencies.

The primary objective is:

> An agency should be able to take its existing mandate/property data in almost any common format, upload it to QuickProp, have the system automatically detect and structure the listings, review them, correct anything necessary, and then publish them in bulk.

The system must dramatically reduce the time required for an agency to onboard its existing property portfolio.

---

# 1. CORE USER JOURNEY

The ideal workflow is:

**Upload existing agency data**

↓

**QuickProp analyses the data**

↓

**QuickProp identifies individual properties/listings**

↓

**AI structures the information**

↓

**Potential duplicates are detected**

↓

**Missing/ambiguous information is flagged**

↓

**Agent reviews the proposed listings**

↓

**Agent edits anything necessary**

↓

**Agent selects listings to publish**

↓

**QuickProp creates/updates canonical property records**

↓

**Listings go live**

The entire process should feel like:

> **"Upload your property database → QuickProp does the work."**


# 12. DUPLICATE DETECTION

This system MUST integrate with QuickProp's canonical-property architecture.

Before creating any property:

Check whether QuickProp already has a matching property.

Match using combinations of:

* address
* GPS/location
* property reference
* suburb
* property characteristics
* existing images
* owner/property identifiers where legitimately available
* fuzzy address matching

Examples:

```text
12 Borrowdale Brooke
12 Borrowdale Brooke, Harare
12 Borrowdale Brooke Estate
House 12, Borrowdale Brooke
```

should potentially resolve to the same canonical property.

Do not blindly create four properties.

# 17. MANDATE VALIDATION

Where mandate dates are available, flag:

Mandate currently valid.

### Expiring soon

* infer
* normalise
* match
* suggest
* flag

**Property type = House**

**Townhouse**

# 43. IMPORTANT: DO NOT PUBLISH DURING AI PROCESSING

AI extraction must NEVER directly publish listings.

There must always be an explicit agent approval step.

The safest architecture is:

```text

↓
Extract
↓
AI interpretation
↓
Draft
↓
Human review
↓
Approval
↓
Publish
```

# ACCEPTANCE CRITERIA

The implementation is complete when:

* Agents can upload Excel, CSV, PDF, Word and image files.
* Multiple files can be uploaded simultaneously.
* QuickProp can extract structured property information from those files.
* Excel columns are automatically mapped.
* Agents can correct column mappings.
* PDFs can be parsed into individual property records.
* Scanned PDFs can use OCR.
* Every imported record starts as a draft.
* AI confidence scores are displayed.
* Low-confidence records are flagged.
* Agents can bulk edit records.
* Agents can filter and sort imported records.
* Duplicate properties are detected before creation.
* Existing canonical properties can be matched.
* Multiple agent/property relationships are supported.
* Agent assignments can be detected and reviewed.
* Mandate information can be extracted and validated.
* Images can be associated with properties where possible.
* Agents can bulk approve and publish listings.
* Critical validation occurs before publishing.
* Original source files are preserved.
* Every AI correction and agent correction is auditable.
* Import sessions can be resumed.
* Large imports are processed asynchronously.
* Agencies are completely isolated from each other's data.
* Repeat imports can detect changes from previous imports.
* No listing is automatically published without agent approval.
* No duplicate canonical property is created simply because of an import.
* The entire workflow is desktop-first and optimised for high-volume agency onboarding.
