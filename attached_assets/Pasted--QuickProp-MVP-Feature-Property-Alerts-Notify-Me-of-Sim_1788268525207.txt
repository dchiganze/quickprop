# QuickProp MVP Feature: Property Alerts & "Notify Me of Similar Properties"

## Objective

Build a property notification/alert system for QuickProp that allows prospective buyers and renters to tell QuickProp what type of property they are looking for and automatically receive notifications when matching properties are listed.

The feature must work for both:

* Prospective buyers
* Prospective renters

The user should be able to:

1. Create a property search/alert using detailed parameters.
2. Receive notifications when a matching property is listed.
3. From any property listing, tap **"Notify me of similar properties"** to instantly create an alert based on that property.
4. Manage, edit, pause and delete their alerts from their existing profile.

The feature should integrate with the existing QuickProp prospective buyer/renter profile and existing property database.

Do NOT create a separate account or profile system.

# 14. Property Match Logic

Whenever a property is:

* Created
* Published
* Updated from draft to published
* Re-listed

run the property against active property alerts.

If it matches, create a notification event.

A property should only trigger a notification if it is currently active/published.

Do not notify users about:

* Draft properties
* Deleted properties
* Expired properties
* Sold properties
* Rented properties

unless the product specifically supports those statuses.

---

# 15. Matching Algorithm

Create a simple but robust matching system.

### Hard criteria

The following should normally be treated as hard filters:

* Buy vs rent
* Property type
* Location
* Maximum price
* Minimum bedrooms
* Minimum bathrooms
* Explicitly required amenities

### Soft criteria

These can contribute to match quality:

* Preferred amenities
* Furnishing
* Parking
* Solar
* Borehole
* Pool
* Other optional features

Calculate an internal match percentage.

Example:

### 92% Match

**3 bedroom house in Borrowdale**

$1,050/month

✓ Price
✓ Location
✓ Bedrooms
✓ Bathrooms
✓ Pool
✓ Borehole
✓ Secure parking

The match percentage should be used primarily for ranking, not necessarily shown to the user unless useful.

# 17. Similar Property Tolerance

The "similar properties" alert should NOT be an exact duplicate search.

Create reasonable tolerance around the source property.

For example:

If source property:

**$1,000/month**

similar alert might initially search:

**$900–$1,100**

If source property:

**3 bedrooms**

similar properties could include:

**3–4 bedrooms**

If location is:

**Borrowdale**

prioritize Borrowdale but potentially include nearby areas if the user allows similar locations.

However, do not make the tolerance excessive.

The user should be able to edit the alert.

Show:

> **Your similar property alert**
>
> Price: $900–$1,100
> Location: Borrowdale
> Bedrooms: 3+
> Property type: House

# 20. Avoid Notification Spam

A user must NOT receive repeated notifications for the same property.

Create a notification history.

If a property has already triggered an alert for that user, don't send it again unless the property has materially changed and the system determines that it should be treated as a new opportunity.

Also prevent the same property from triggering multiple identical alerts unnecessarily.

Example:

If a user has:

**"3 Bedroom Borrowdale"**

and

**"Borrowdale House"**

and both match the same property, consolidate notifications where appropriate rather than sending two separate notifications.

# 23. Agent/Seller Benefit

The alert system should also benefit property suppliers.

When an agent or owner publishes a property, QuickProp should immediately check whether there are prospective buyers/renters looking for that type of property.

This creates a powerful supply-demand connection:

**New property listed**

↓

**QuickProp finds matching prospective buyers/renters**

↓

**They receive notification**

This should happen automatically.

Do not expose personal information about prospective buyers/renters to agents unless the user has explicitly made their contact/application information available.

# 27. Performance

The system must be designed to scale.

Do not run an expensive full database search against every alert synchronously every time a property is created.

Use an appropriate background job/queue architecture if supported by the existing QuickProp stack.

For MVP, a simple implementation is acceptable, but structure the matching service so it can later scale to:

* Thousands of properties
* Thousands of alerts
* Multiple notifications per day

---

# 28. UX Principles

The feature must be:

* Very fast
* Mobile-first
* Simple
* Visually clean
* Easy to understand
* Minimal typing
* Primarily dropdowns, buttons and chips
* Consistent with existing QuickProp UI

The user should be able to create a basic alert in **under 60 seconds**.

The fastest possible flow should be:

**Rent → House → Borrowdale → $800–$1,200 → 3+ bedrooms → Create Alert**

---

# 29. Important: Do Not Overcomplicate the MVP

Do NOT build:

* AI property recommendations
* Complex machine learning
* Credit scoring
* Automated affordability calculations
* Complex geospatial algorithms
* Predictive property recommendations
* Complicated lead scoring

The MVP is simply:

### "Tell QuickProp what you want, and we'll tell you when it appears."

And:

### "See a property you like? Tap one button and we'll notify you about similar properties."

---

---

# Final Implementation Requirement

Before writing new code:

1. Inspect the existing QuickProp codebase.
2. Identify the existing user/profile system.
3. Identify the existing property, property type, location and amenities structures.
4. Identify the existing notification infrastructure.
5. Reuse existing components and design patterns.
6. Do not create duplicate authentication, user, property or location systems.
7. Make the feature fully integrated into the existing QuickProp prospective buyer/renter experience.

Build the feature end-to-end, including:

**Frontend UI → database → alert creation → property matching → notification generation → notification history → alert management → "Notify Me of Similar Properties" button.**

The result should be production-ready MVP functionality rather than a static UI mockup.
