Project Overview
Build the QuickProp Administration Portal, the operational control centre for the QuickProp ecosystem.
QuickProp consists of four applications that MUST share a single backend:
1.	Public Website
o	Property search
o	Buyer enquiries
o	Property discovery
2.	Agent Mobile App
o	Upload property mandates
o	Manage listings
o	Receive and manage leads
o	Generate WhatsApp catalogues
3.	Agency CRM
o	Agency inventory management
o	Lead management
o	Team management
4.	QuickProp Administration Portal
o	Marketplace oversight
o	Vendor management
o	Property moderation
o	Lead intelligence
o	Platform analytics

CRITICAL ARCHITECTURE REQUIREMENT
This is NOT a separate application.
The Admin Portal MUST use:
•	The same PostgreSQL database
•	The same backend
•	The same REST API
•	The same authentication service
•	The same notification system
•	The same storage system
•	The same image repository
There must only ever be one source of truth.
All four products must remain synchronised in real time.
Example:
Agent uploads property in App
↓
Database updates
↓
Website listing appears instantly
↓
Agency CRM inventory updates
↓
Admin Portal statistics update automatically
No duplicated databases.
No duplicated APIs.
No duplicated authentication.
No duplicated business logic.

Core Philosophy
This is not simply an admin CRUD panel.
It is the operational control centre for the entire QuickProp marketplace.
Every screen should help answer one of these questions:
1.	Are we increasing property mandate coverage?
2.	Are buyers finding suitable properties quickly?
3.	Are agents responding to enquiries efficiently?
4.	Is marketplace activity growing?
5.	Is the quality and freshness of listings improving?
The system should provide administrators with complete visibility across the Website, Agent App, Agency CRM and Marketplace, while maintaining a single shared backend, single database, and real-time synchronisation across all QuickProp products.
Organise the backend as a modular monolith rather than microservices. At the MVP stage, one well-structured codebase with modules such as Auth, Users, Agencies, Properties, Leads, Notifications, Analytics, and Admin is far easier to build, test and maintain. All four front ends (Website, Agent App, Agency CRM and Admin Portal) would consume the same APIs. If QuickProp eventually scales to millions of users or expands into other countries, individual modules can later be extracted into microservices without rewriting the entire platform. This architecture gives the fastest path to a robust MVP while leaving plenty of room to grow.
